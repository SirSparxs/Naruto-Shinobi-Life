## Documentation-level scenario review

These are consistency checks against the written contracts, not runtime engine tests.

| Scenario | Required interpretation after integration |
|---|---|
| Newly acquired jutsu at low mastery | Rough functional use, separate from unknown/partially acquired state |
| Basic V versus generic Tier V | Different tracks; no automatic equality or shared growth coefficient |
| Passive hereditary skin trait | No mandatory ability-proficiency bar |
| Minor execution variant | May share familiarity; no blanket reset to zero or automatic full-copy mastery |
| Clones repeat physical drills | No transfer of cloned muscle growth; learning is filtered and assimilated |
| Perfectly observe a bloodline jutsu without its biology | Information retained; reproduction remains blocked |
| Adopted child learns Hiden | Educational access can exist without genetic lineage |
| Transplanted eye gives enhanced perception | No donor mastery, inherited reproductive trait or automatic bodily speed |
| Transformation enables a learned technique | Permission/capability can be temporary; no automatic permanent learning |
| Two attacks do not intercept | Both can succeed; shared-contest rule does not forbid it |
| Technique interrupted after resource investment | Relevant spent/locked resources and backlash are recorded |
| Absorber has capacity but inadequate rate | Not automatic immunity; throughput remains binding |
| Suppressing seal blocks a full pool | Available access changes without pretending all stored chakra vanished |
| Caster loses consciousness after placing an independent seal | Effect follows its own lifecycle rather than automatic deletion |
| Sensor identifies genjutsu | Detection does not itself complete escape |
| Medic diagnoses an injury | Diagnosis does not itself heal it or erase physiological prerequisites |
| Prototype provides useful failed-test feedback | Persistent learning can advance without declaring functional mastery |
| NPC becomes relevant | Instantiate from history before use; do not generate a perfect counter retroactively |
